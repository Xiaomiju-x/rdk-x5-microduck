# 保留的未完成功能拓展

**2026-10-30 结项后留档。以下不是当前功能、待办排期或交付承诺。项目不再主动推进。**

保留两条有明确用途的设想：让南瓜面具承担感知与表达，让瓜园成为有真实触发和反馈的互动场景。现有硬件、结构和数字版可以供后来者研究；任何重新实施均应另建版本并重新确认实际设备状态。

## 一、南瓜面具：看到、听到、作出可见回应

| 拓展 | 面具的具体作用 | 当时已有基础 | 尚未完成及未来验收依据 |
|---|---|---|---|
| 访客发现与方向判断 | 相机从“鼻子”位置观察面前的访客 | 相机及打印托架安装结构 | 实际视野/灯反光、检测软件、多访客及目标消失测试；须有当前相机实拍与误触发记录 |
| 固定口令与播报 | 麦克风收音，笑嘴开口出声 | 语音模块及 R1b 平托板 | 活动词表、实际固件/串口合同、口令到事件映射和播报回授抑制；硬件装上不算软件完成 |
| 南瓜灯眼表达 | 用不同灯态显示等待、发现、完成、不可用 | 灯孔与 LED 压片 | 真实通道、限流/供电、可见亮度和状态对应关系；不把 CAD 灯色当亮灯实测 |
| 头嘴与灯声配合 | 让角色点头、好奇、回应口令 | 机器人头嘴关节与数字演示 | 当前装载的机械净空、权限互斥、真人触发与完整退出；不能直接把游戏录制动作发到机器人 |
| 完整面具载荷验收 | 保持附件、插头和线束在实际动作中稳定 | 可拆结构及已有实物 | 记录模块和线束实际重量、安装位置、视场、站姿与有限动作；旧不同配置行走视频不替代本项 |

## 二、瓜园：真实触发 → 机构动作 → 结果反馈

以下是保留的编排设想，不是已经完成的实物流程：

```text
访客或固定口令
    → 面具灯眼/声音回应
    → 选择一个瓜园工位
    → 请求该机构做一次有限动作
    → 检查真实开关、视觉或操作者反馈
    → 完成提示 / 等待 / 取消并说明原因
```

| 模块 | 互动意图 | 还缺什么 |
|---|---|---|
| 眨眼南瓜（桌面 2） | 发现访客时眨眼或显示表情 | 正确主动输出联接、插头与线束净空、实际可用角度和返回位置 |
| 孵化平台（桌面 3） | 平台升起呈现小鸭，黄灯显示到位 | 当前平台/立柱/轻薄壳装配后的全行程、孵化 KW11 真实触发、软件反馈；不用盲目整圈扫转代替端点验证 |
| 放籽转门（桌面 4） | 放行一颗种子，确认有籽或缺货 | 真实种子/接触和出料路径、卡住/缺货反馈与一次一颗逻辑 |
| 五瓣宝盒中央转台（桌面 5） | 有限角度切换南瓜/鸭头视面，再返回 | 主动轴传动、A/B 实测位置和净空；五瓣外观装配不等于自动开瓣功能完成 |
| 幻影栅格（桌面 6） | 左右滑动栅格改变观看效果 | 固定与驱动联接、打印后滑动阻力、边界与返回位置、实际光照下效果 |
| 全场协同 | 把回应、送籽、孵化和展示串成简短体验 | 事件状态机接入真实硬件、跨模块互斥、真人完整演示和失败恢复 |

## 三、保留异常分支，但不混同数字与实物验收

| 分支 | 数字版已有记录 | 实物仍需验证 |
|---|---|---|
| 等待 | 游戏状态与路线测试 | 真实超时、开关未触发、等待时机构保持及取消 |
| 遮挡 | 数字场景分支 | 相机真实遮挡、目标丢失/恢复；无证据时不猜机构结果 |
| 缺货 | 游戏中的缺货状态 | 真实无籽/卡籽判定、提示和补货后复位 |
| 停止/退出 | 软件流程和回放边界 | 实际舵机、灯与声音的停止语义、未知位置处理和重新开始 |

最后的握手叶片 KW11 已取消，不作为结项时装配的功能，也不在上述保留方案中悄悄恢复。

## 四、数字版可参考的范围

现有 Web / UE5 包保留故事编排、视角、昼夜、主题色/白色和动作回放。未来若有人继续，可用它们沟通交互想法，但必须另行验证真实传感器、机械动作与新增载荷。仿真质量、ONNX 数值一致或故事流程通过均不直接授予实体部署资格。

本项目不为以上设想继续安排 GPU、采购、打印、自动化或联调；也不将它们并入仍在推进的机器鸭主线。
