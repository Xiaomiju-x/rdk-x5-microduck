# RDK X5 Duck 完整案例：从硬件、装配、软件与仿真到机载短距离前进

**本案例围绕现有 RDK X5 开发板，完整说明如何搭建一台飞特舵机机器鸭，并建立可继续改进的控制与仿真环境。** 原型已在计算板、驱动板和电池全部上身的条件下实现短距离前进。本次把采购、打印、接线、软件、模型、首次运行和调试方法按复刻顺序组织起来。

> 固定版本：v2026.10.27.1。原型短距离实拍：2026-10-23。读者既可以从零采购搭建，也可以先在没有硬件的电脑上体验控制台与仿真。

- 项目仓库：https://github.com/Xiaomiju-x/rdk-x5-microduck
- 固定版本与完整下载：https://github.com/Xiaomiju-x/rdk-x5-microduck/releases/tag/v2026.10.27.1

## 1. 案例目标与实际成果

本项目想解决的是：用可获得的开发板、串口总线舵机和3D打印结构，建立一套能够装起来、读得回、动得起来、便于逐轮调试的机载双足机器人参考系统。

RDK X5是计算与控制主机，微雪小板负责USB与舵机总线的连接，15只飞特HD1910M驱动双腿、头颈和嘴部，JY901S提供惯性数据。当前短距离动作运行于X5，电脑用于打开页面、调参和观察。

[![全机载短距离前进与硬件展示](images/video-cover.jpg)](../media/20261023/onboard-short-walk.mp4)

完整视频约13秒，前段是短距离前进，后段展示机载板卡与供电。演示末段保持站立。这是已取得的实物结果；视频并不表示13秒一直行走。

![成功原型配置卡](images/prototype-configuration.png)

成功原型的主要装载关系是：X5在背侧竖装，两块蓝电池分置机体两侧，微雪贴在其中一块外侧，前下方有棕色附加安装/配重件。IMU在这两张照片中被遮挡，不能据此猜测精确安装落点。完整整机质量、棕色件质量和部分安装基准距离仍需补测；[配置卡](PROTOTYPE_CONFIGURATION.md)区分已知信息与待测项。

| 验证对象 | 当前结果 | 复刻者如何理解 |
|---|---|---|
| 原型全机载短距离前进 | 已有完整实拍与保存参数 | 说明该硬件路线取得过实物前移结果 |
| 公开D运行包 | 软件检查及与原位置包的离线等价对照 | 可获取源码与动作基线；仍需对自己的机器做首次验证 |
| 连续2/3/5轮 | 已实现完整周期重复并离线验证 | 不直接等于更长距离或连续稳定行走已经验收 |
| FT教学仿真 | 可加载模型并运行小幅关节实验 | 用于理解几何、关节、单位与模型参数，不代替实机证据 |
| 全身RL闭环、长距离、单电池 | 后续研发路线 | 本次资料释放不等待这些目标全部完成 |

## 2. 系统全景：每块硬件和每层软件负责什么

![系统全景框架](images/system-framework.png)

### 2.1 硬件层

| 模块 | 输入 | 输出 / 职责 |
|---|---|---|
| RDK X5 | 浏览器操作、IMU数据、舵机回复 | 机载Python控制、动作调度、数据处理和记录 |
| 微雪 Bus Servo Adapter (A) | X5 USB数据、独立动力电源 | TTL舵机总线收发；不是步态计算器，也不是任意电压降压板 |
| 15轴HD1910M | 原始位置目标 | 关节运动；回复实际位置、使能与故障等状态 |
| JY901S + USB-TTL | 机体运动 | 欧拉角、角速度等串口数据 |
| 两路供电 | 两块成品电源 | 分别供计算系统与舵机动力支路 |
| FT结构 + R8A支架 + TPU脚垫 | 舵机输出与载荷 | 形成关节、承力连接、机载安装和脚底接触 |

微雪的两个舵机接口是同一总线的两个分支，不能因此给不同舵机重复ID。X5到微雪的USB线负责数据，不替代动力供电。具体接线和针脚见[HARDWARE](../HARDWARE.md)。

### 2.2 软件层

公开软件统一放在 `software/`。每个模块尽量对应一个清楚的职责：

| 文件 / 目录 | 作用 | 复刻时需不需要改 |
|---|---|---|
| `app.py`、`web/` | 本地Web服务、任务互斥、参数、进度与记录 | 初次使用不需要 |
| `runtime.py` | 计划、检查、捕获START、慢复位、运行完整周期 | 初次使用不需要 |
| `data/d_trajectory.json` | 400帧基准腿部/全身相对目标与节奏 | 保留原基线后再研究修改 |
| `neck.py` | 11号颈根分段角度、平滑过渡与提前回位 | 日常通过控制台改参数 |
| `parameters.py` | 参数格式和轮数定义 | 初次使用不需要 |
| `feedback.py`、`bounded_read.py`、`confirm_write.py` | 读回和协议交互流程 | 初次使用不需要 |
| `imu.py` | JY901S传感器数据接收与解析 | 安装方向写在设备配置里，由运行器转换到机体方向 |
| `imu_diagnostics.py` | 独立IMU只读检查、机体轴转换和包频率统计 | 初次安装时按教程使用 |
| `contract.py` | 位置包与设备约定检查 | 不用它修正错误机械安装 |
| `config/robot.example.json` | 新机器的配置模板 | 复制为自己的本地配置后填写 |
| `config/success_20261023.json` | 成功原型颈部参数基线 | 可对照，不是通用绝对零位 |
| `tests/` | 无硬件的软件测试 | 可运行、可扩展 |

程序执行在X5；浏览器发起的是任务和参数，不是由网页逐拍实时控制舵机。页面使用SSH端口转发访问X5本机服务。这样无需给机器人开放公网运动接口。

### 2.3 三种环境各自做什么

- **软件DEMO：**不接串口，演示控制台和任务流程，适合先熟悉按钮与轮次。
- **MuJoCo教学仿真：**在电脑上加载FT几何模型、观察关节并做小幅动作，适合理解模型及后续参数辨识。
- **实机D运行：**X5读取本机状态、按轨迹与颈部时序下发目标，需要正确装配和逐机配置。

DEMO不是动力学仿真，教学仿真也不自动成为成功实机动作的数字孪生。后续RL研究从对齐模型与反馈开始，见第11章。

## 3. 选择复刻路线与准备工作

![复刻流程与每步产出](images/reproduction-map.png)

### 路线A：先不买硬件

下载固定Release → 建立Python环境 → 跑测试与DEMO → 加载MuJoCo模型 → 看懂动作、坐标与日志。完成后再决定采购和打印，避免在不了解结构版本时混买不同舵机。

### 路线B：已有飞特FT鸭子

先确认现有本体、舵机型号和ID → 对照本项目接线 → 使用R8A等增量件安装X5 → 建立自己的设备配置与START → 悬空检查 → 落地单轮观察。不要为了套本仓库而先改掉一套已经确认有效的机械零位。

### 路线C：从零搭建

按[采购清单](PROCUREMENT.md)与[52对象选件表](FT_PRINT_SELECTION.csv)准备 → 打印本体与增量件 → 逐轴编号与装配 → 板卡安装和布线 → 系统与传感器接入 → 初始站姿 → 单轮调试。

### 工具与工作区

准备适配紧固件的螺丝刀/内六角工具、清理支撑的小工具、卡尺、万用表、绝缘与固定辅料、平整防滑测试面。可用3D打印机或外部打印服务。称重工具用于记录自己的整机和附加件数据，不需要先达到一个虚构的“统一重量”。

打印机配置以本包标明的机器/喷嘴/耗材为基线；其他设备必须重新切片。所有“左/右”均按鸭子自身方向。

## 4. 硬件选型、采购与供电

### 4.1 核心器件

| 器件 | 数量 | 选择理由与关键匹配项 |
|---|---:|---|
| RDK X5完整开发板 | 1 | 现成Linux计算平台，USB连接驱动和传感器；本版不是Module |
| 飞特HD1910M | 15 | 对应FT打印结构和本项目协议/安装；两腿各5、头颈4、嘴1 |
| 微雪Bus Servo Adapter (A) | 1 | X5 USB与TTL舵机总线连接；型号包含 `(A)` |
| JY901S + USB-TTL | 各1 | 独立惯性数据链路；核对电平、供电、波特率和输出类型 |
| X5电源、舵机电源 | 各1 | 当前双路方案；外置适配器可用于初次联调 |
| microSD、USB数据线、三线总线 | 按清单 | 数据线要能传数据；连接器针序和线长按实装核对 |
| 本体、安装件、脚垫与五金 | 按选件表 | 不把所有上游备选件都装到一台机器上 |

完整规格、采购检索词、可替代条件、固定来源及数量见[PROCUREMENT](PROCUREMENT.md)。未保存商家准确型号的零件会标明，不能只看“蓝色电池”“相同外形”下单。

### 4.2 当前供电结构

```text
电池A（USB-C输出） → X5电源USB-C
X5 USB HOST → USB数据线 → 微雪USB-C（USB控制档）
电池B（DC输出） → 微雪动力输入 → 舵机两路分支
X5另一USB HOST → USB-TTL → JY901S
```

X5与舵机的负载特性不同：计算支路需要稳定供电；舵机支路在起步、承重和关节加速时会有动态负载。电源铭牌相同或静态电压接近，不能保证带载时表现完全相同。

RDK官方电源要求、微雪接口及本原型采用的电源规格在[HARDWARE](../HARDWARE.md)分别列出。本案例记录双电池原型，不把它外推成所有X5外设与算力工况的通用供电推荐。单电池属于后续专项，不在复刻时临时把两个输出接在一起。

### 4.3 总线分支

本原型记录的支路为：

```text
微雪口1 → 左腿01～05 → 头颈/嘴11～15
微雪口2 → 右脚踝10 → 09 → 08 → 07 → 06
```

D/V/G一一对应，按接口标注核对，不按线色猜测。两腿不再保留多余跨接形成环路。首次给ID编号时一次连接一颗，并记录它安装到哪个物理关节；完整本机映射见[15轴表](../HARDWARE.md#4-15个舵机id与已观察方向)。

## 5. 机械文件、打印与装配

### 5.1 选定版本，先看清单再开打

本体来自机械行者Robo / fanhao375的FT复刻结构，选用飞特v2.0对应件。不要把XL330原版、陆吾结构和FT接口混装。公开目录按用途区分：

- **FT本体件：**建立头颈、躯干、腿和脚掌的原结构。
- **R8A改件：**L1根座×1、L2 X5安装架×1、6mm隔套×4。
- **TPU脚垫：**左右各一件，仍保留硬脚掌与脚踝。
- **可选/排除件：**依最终选件表处理，不因为在上游盘里就全部打印。

本版选定28个本体硬件件，加R8A六实体和左右TPU两件，共34个硬件实体与2个脚底套。[52对象选件表](FT_PRINT_SELECTION.csv)逐项说明哪些使用、替代或不使用；[BUILD_CHECKLIST](BUILD_CHECKLIST.md)按步骤执行核对。[机械目录](../mechanical/README.md)列文件来源、许可与校验信息。

### 5.2 材料与切片

本体和安装件采用PLA，脚底套采用TPU95A HF。R8A的根座、托架和隔套不是统一一个填充率：承力部位与一般托架分别配置。具体墙数、填充和支撑见[ASSEMBLY](../ASSEMBLY.md)。

公开3MF是可编辑工程，使用本包标明的P1S/0.4mm/纹理PEI基线，需自己重新切片。TPU95A HF使用外置料架。不是把整机材质都改为软料，也不是把任意打印机直接当P1S发送。

打印后先清理支撑，确认细筋、托指和螺母槽未被误剪；用螺母与螺丝离机试装，再把板卡装上去。

### 5.3 装配顺序与关键检查

| 顺序 | 操作 | 完成后检查 |
|---|---|---|
| 1 | 逐颗舵机编号并记录物理位置 | 无重复ID；型号、模式与本项目要求对应 |
| 2 | 组装腿部、躯干与头颈 | 左右件、驱动盘/副盘和轴承配合正确；无强拧消除的卡滞 |
| 3 | 用L1替换对应原底座 | 原腿根尾端孔位对应；不把舵盘中心螺钉当承力安装孔 |
| 4 | 将四颗M2螺母预先放入L2 | 下方两颗有装入通道，能放入也能拧紧 |
| 5 | 用M3连接L1和L2，再装X5与隔套 | 接触面贴合、PCB不压焊点、接口可插拔 |
| 6 | 按实装固定电池、微雪与IMU | 固定在正确刚性部位；电源线不承担部件重量 |
| 7 | 更换TPU脚垫并收线 | 左右贴合、防脱；活动关节不会夹线或拉紧插头 |
| 8 | 建立本机站姿和配置记录 | 拍正侧背图，记录硬件、安装与参数版本 |

## 7. 第一次接入舵机与IMU

### 7.1 不直接复制别台机器的标定

本机固定ID为1～15，HD1910M舵机总线为1Mbaud，JY901S示例115200baud。左右定义按鸭子自身。3号是左髋俯仰，8号是右髋俯仰；它们计数增加时在机体方向上的表现不同。11号颈根计数增加后移、减小前移。

上游工具可用于单颗编号与模式配置，但其默认整机编号和IMU体系与本项目不同。**复用工具的具体功能，不照搬上游整机默认配置。** 本项目公开运行器不自动改ID、模式、offset或P/D。首次配置的逐步操作见[FIRST_RUN](FIRST_RUN.md)。

### 7.2 创建自己的配置

```sh
python -c "from pathlib import Path; import shutil; Path('.local').mkdir(exist_ok=True); shutil.copyfile('config/robot.example.json','.local/robot.json')"
python -m serial.tools.list_ports -v
```

编辑自己的 `.local/robot.json`：

| 字段 | 内容来自哪里 |
|---|---|
| `servo_port`、`imu_port` | 本机枚举出的两个不同串口；Linux可用稳定by-id路径 |
| `expected_mode`、`expected_offsets_raw` | 本机实际读取，确认与运行约定一致 |
| `start` | 本机正确站姿下的15轴位置快照 |
| `directions_verified` | 实际逐轴确认后记录，不是为了通过程序随手勾选 |
| `body_from_sensor_rotation` | 由IMU固定安装方向确定 |
| `start_pose_verified`、`imu_mount_verified` | 完成相应观察后确认 |

模板与历史原型示例都不是拿来直接运动的设备配置。建议把装配图、设备信息和本地配置一起保存为自己这台机器的记录。

### 7.3 先检查两个数据链路

舵机只读检查：

```sh
python runtime.py inspect --robot .local/robot.json
```

它应读到15只舵机的状态。IMU使用独立只读检查入口：

```sh
python runtime.py imu-check --robot .local/robot.json --seconds 8
```

该入口只打开IMU串口，输出原始传感器轴、机体重力/角速度、相对前后倾变化、0x52/0x53频率与数据年龄；不向舵机发任何指令。具体观察方法与输出见[FIRST_RUN](FIRST_RUN.md)。两个数据链路分别判断，不能以舵机可读代替IMU已经可用。

JY901S需输出欧拉角0x53和角速度0x52；本项目数据率约50Hz。程序只读，不配置传感器。安装后核对机体坐标：X朝嘴巴、Y朝鸭子左侧、Z向上。支撑机体做小幅前后倾，用预期符号验证方向。常见安装方向矩阵示例与图解在首次运行教程中。

## 8. 建立本机START与首次动作

### 8.1 START代表什么

START是这台机器人在选定初始站姿下的关节快照。它与机械舵盘安装、硬件offset以及身体姿态有关；不是所有鸭子通用的一组数字。相对动作的映射是：

```text
本机关节目标 = 本机START + 已验证方向下的基准增量
```

即使换了START，仍然需要结构、ID、方向和起始几何相符。不能把任意站得住的姿态都当成等价初始状态。

### 8.2 只读捕获与慢复位

支撑机体，参照本项目站姿与关节图完成摆放，再捕获：

```sh
python runtime.py capture --robot .local/robot.json --output .local/captured_robot.json
```

连续三次读取用于检查姿态没有明显移动。捕获不修改舵机寄存器；核对输出后，才将它作为自己的设备配置。

托稳躯干和头部、双脚卸重后慢复位：

```sh
python runtime.py restore --robot .local/robot.json --supported
```

若只有部分关节可按当前检查条件恢复：

```sh
python runtime.py restore --robot .local/robot.json --supported --partial
```

查看返回的完成与跳过名单，不能把“部分完成”当成全机站姿已经恢复。实际站稳需现场观察。

### 8.3 在X5运行，电脑浏览器访问

X5终端：

```sh
python app.py --robot .local/robot.json --port 9194
```

电脑另一终端：

```sh
ssh -L 9194:127.0.0.1:9194 your_user@your_x5_address
```

浏览器打开 `http://127.0.0.1:9194/`。两端使用相同端口；如果端口被旧服务占用，换同一个新端口，并明确自己打开的是哪一个服务。首次观察顺序为：只读设备 → 托稳复位 → 悬空动作 → 落地单轮。打开页面、切换轮数和保存参数本身不发动作。

## 9. D短动作、颈部时序与控制台

### 9.1 一轮究竟包含什么

D保留了原调试过程中能够产生缓慢前移的短目标片段，再对11号颈根加入分段角度与提前收颈。它不是本次新训练得到的全身RL策略。

| 阶段 | 帧数 | 作用 |
|---|---:|---|
| 准备 | 150 | 准备与启动颈角渐入 |
| 短动作 | 100 | 腿部基准片段，颈根向走动角过渡 |
| 平滑回位 | 100 | 腿部返回原参考；颈部可提前开始回位 |
| 保持 | 50 | 完整单轮的结束保持 |

![D目标时序与提前收颈](images/d-timing.png)

轨迹名义节奏与实际串口耗时应分开理解。参数秒数不代表实物关节会在严格相同的墙钟时间内到达指定角度。

### 9.2 保存的成功参数

| 控制项 | 保存值 | 说明 |
|---|---:|---|
| 启动角 | 0° | 相对本机START |
| 走动角 | 请求前移30°，代码−30 | 只作用11号颈根 |
| 起步保持 | 0秒 | 进入走动后开始过渡 |
| 角度过渡 | 0.2秒 | 平滑变化 |
| 提前收颈 | 1.1秒 | 相对原收尾时序提前 |
| 自动前/后反馈 | 0 / 0 | 成功配置采用定时配合 |

前移30°是请求目标，每拍变化速度和提前回位会共同影响实际发送的目标曲线；更不能把它直接解释成身体俯仰30°。完整参数定义见[成功配置](../progress/2026-10-23/README.md)。

### 9.3 根据发生阶段微调

| 现场现象 | 优先看什么 | 一次只改一项 |
|---|---|---|
| 刚启动向前倒 | 初始站姿、启动时头颈配合 | 在已核方向下，小步调整启动角 |
| 中段逐渐向后倒 | 走动时重心与颈部位置 | 调整走动角，保留启动角用于对照 |
| 最后向前倒 | 颈部回位是否过晚、腿部是否跟随 | 调整提前收颈时间 |
| 原地动、没有可观察前移 | 动作是否完整执行、目标与实际是否一致、脚底接触 | 先记录和定位，不同时改多个幅度 |
| 左右明显不对称 | ID、方向、机械、供电支路与跟随 | 分关节对照，不能靠颈角掩盖装配问题 |

观察视频最好包含双脚、全身和完整起停过程。记录“哪一阶段、朝哪个方向、是否接护”，比只写“失败”更能帮助继续调试。

### 9.4 连续轮的用法

1、2、3、5轮重复的是完整400帧周期，不是把中间100帧硬循环。每轮重新建立时序与IMU参考；停止、通信异常或上一轮未完整完成时不进入下一轮。多轮是延长短段实验的入口，实际距离和站稳效果由现场验证。

## 10. 仿真环境：模型、运行与输出

本版把仿真作为独立章节和独立目录提供，避免“有个模型链接”却不知道如何运行。

### 10.1 本版仿真解决什么

在电脑上加载FT几何，识别关节树和轴向，观察静态参考及小幅关节往返，记录摆幅、最大跟随误差等摘要，并为后续质量、惯量和执行器辨识建立基础。

教学模型采用FT CAD衍生几何，不能把上游XL330模型、陆吾XGO模型与FT机体混为一谈。总质量基线来自历史裸机记录，逐连杆分配、惯量与执行器参数仍含工程假设；本次成功实机的双电池、X5和附加配重不能凭外观无差别套入。

### 10.2 环境、入口和结果

完整命令、固定依赖、模型来源、脚本参数、无窗口运行与可视化方式见[SIMULATION](../SIMULATION.md)。所有文件集中在 `simulation/`，与 `software/` 的串口控制路径分离。

仿真流程为：创建独立Python环境 → 安装MuJoCo依赖 → 检查模型关节数/单位/质量 → 运行小幅实验 → 读取JSON与图像输出。这个过程在电脑执行，不需要X5上电，也不连接舵机串口。

安装 `simulation/requirements.txt` 后，在仓库根目录用仿真环境的Python运行：

```sh
python simulation/run.py inspect --output simulation/.local/inspect.json
python simulation/run.py hold --seconds 2 --output simulation/.local/hold.json
python simulation/run.py joint --seconds 2 --image simulation/.local/preview.png --output simulation/.local/joint.json
```

三条命令依次是模型检查、自由基座短保持、固定躯干的双膝小幅实验。Windows将 `python` 换为 `simulation/.venv/Scripts/python.exe`；第三条PNG需要OpenGL，前两条不需显示器。

![FT裸机教学模型，MuJoCo实际渲染](../simulation/media/ft-reference.png)

[2秒教学视频：固定躯干的双膝响应，非行走演示](../simulation/media/ft-joint-teaching.mp4)

本次实际完成15关节/14执行器模型加载、2秒400步保持和双膝实验。预期看到的是FT简化教学模型和小幅关节运动；日志可确认模拟时间、状态是否有限以及实验输出。某段动画没有倒下，不等于真实机器带载行走已通过；固定机体的关节测试主要用于核对运动学和软件接口。

### 10.3 如何改模型

先修改有测量依据的量：零件位置、载荷质量与位置、实际站姿、脚底接触和关节方向。再识别执行器响应、力矩/速度限制与通信延迟。每次改动记录版本，保留原教学配置用于对照。

不要通过改真实机器标定去勉强凑仿真姿态；也不要为了仿真看起来稳定而隐瞒固定基座、额外支撑或质量假设。图像、配置与运行日志一起发布，别人才能理解结果。

## 11. 从仿真走向RL实时闭环

RL实时闭环要形成以下链路：

```text
IMU姿态/角速度 + 关节位置/速度 + 运动命令
                 ↓
        与训练一致的观察量处理
                 ↓
          策略推理 / 动作缩放
                 ↓
           关节目标 → 舵机
                 ↓
          新一拍真实状态反馈
```

本案例当前成功动作主要是轨迹与颈部时序。要验证RL，需要逐项对齐：关节顺序、正方向、单位、零位、观察量归一化、速度滤波、上一拍动作、控制频率、延迟和电机响应。两台鸭子外观相似，不意味着策略可以直接互换。

建议研究顺序是：

1. 固定FT几何与当前载荷的模型版本。
2. 用悬空和带载的小动作测实际响应，调整仿真执行器与延迟。
3. 选用许可明确的训练框架与起始模型，记录代码、随机种子、环境与训练量。
4. 分别评估站立、前进、收步和扰动/载荷变化。
5. 导出策略后核对训练与运行的输入输出一致性，再逐级上机验证。

RTX5090可以用于训练和评估，但GPU资源不是仿真与实机一致性的替代品。[SIMULATION](../SIMULATION.md)给出上游研究入口；[ROADMAP](../ROADMAP.md)列后续RL工作与验收内容。

## 12. 日志、调参和故障定位

公开控制台将每轮参数、执行状态和帧进度记录到本地。实机记录包括目标与反馈；实际是否前移、倾倒方向和是否接护还需要操作者补充。

| 现象 | 先核对 | 应保留的证据 |
|---|---|---|
| 页面能打开，设备不可读 | 是否DEMO、设备串口、总线电源、USB控制档 | inspect输出、接线照片 |
| 部分舵机缺失 | ID重复、分支和插头、单颗模式 | 在线ID清单与逐颗读取 |
| IMU没有数据/符号反了 | 波特率、0x52/0x53输出、安装矩阵 | 独立IMU日志与倾斜方向视频 |
| 悬空正常，承重后不跟随 | 电源动态、机械干涉、载荷与位置误差 | 同目标两种负载的日志 |
| 动作很大却不像步态 | 是否用了不同版本、相对START/方向是否正确 | 配置、动作版本和目标/实际曲线 |
| 中途停住没有回位 | 操作者停止、设备异常或任务未完成 | 末状态和错误信息；不要假定自动复位已经执行 |
| 只在收步倒 | 颈部回位时机、腿部跟随与剩余运动 | 包含收步的完整视频与参数 |

停止命令停止后续目标，不自动卸力或大幅拉回START。需要恢复时由操作者支撑机体并明确复位。详细历史案例见[PITFALLS](../PITFALLS.md)，研发时间线保留在[BUILD_LOG](../BUILD_LOG.md)。

推荐每次只变一个控制参数，记录硬件布局、电源/电量、地面、软件版本与现场现象。同一目标在不同负载和地面上不一定得到同样效果。

## 14. 后续安排：单电池、线束、长距离、RL
