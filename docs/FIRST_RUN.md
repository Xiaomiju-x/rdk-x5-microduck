# 第一次把自己的RDK X5 Duck跑起来

本页将软件命令和实物检查连成一条路线。先完成 [打印装配](../ASSEMBLY.md)、[接线](../HARDWARE.md) 和 [安装环境](../DEPLOYMENT.md)，然后逐步进行。无需先训练策略。

## 1. 每一步应得到什么

| 阶段 | 所需条件 | 可核对的结果 |
|---|---|---|
| 软件离线 | 电脑、固定发布包、Python | 测试OK、plan2000帧/0写、DEMO可打开 |
| 舵机编号 | 单颗舵机、微雪、供电、工具、标签 | 15只唯一ID1–15 |
| 整机只读 | FT本体、两条分支、X5 | 15个ID全部回复、位置对应已记录 |
| 初始姿态 | 支撑物、正侧图、实际读数 | 本机START与硬件offset快照 |
| IMU | 固定JY901S、USB-TTL、轴标识 | 前后倾读数符合实际方向 |
| 首次动作 | 单轮、托稳悬空、线缆自由 | 方向与活动空间正常 |
| 落地观察 | 平整防滑面、接护、固定装载 | 记录前移及起步/走动/收步表现 |

`robot.json`是自己的设备配置。每次修改前备份最后确认的文件，不用仓库原型计数覆盖别台机器。

## 2. 给新舵机编号，已有机保留原标定

**已有正常站姿的鸭子**先保存ID、模式、offset、位置，不因看本教程而重校全部舵机。

**新购散装舵机**在装机前逐只编号最方便，每次总线上仅接一只。可用飞特厂商工具，或 [servo-web固定版本](https://github.com/fanhao375/microduck-replica/tree/f12827cd92272e91276246ac8958482e9bcb6c1f/tools/servo-web) 的单颗操作。其 `--ids` 可自定义扫描范围，但默认范围不是本项目编号。

1. 断开舵机动力电源，总线上只留待处理的一颗。
2. 微雪与电脑/X5用USB数据线连接，按厂商接线说明供电。
3. 扫描并读取实际ID、型号/固件、模式、波特率、offset，保存原始记录。
4. 用单颗“改ID”设置下表中的目标ID，再重新读回。工具若只给另一套标准ID下拉，可用单颗寄存器工具或厂商软件，不能把本项目改成另一套ID。
5. 对照所购HD1910M的固件表确认模式4、1Mbaud。本原型精确固件版本尚未完整归档；不同批次先查厂商资料，不反复盲写模式。
6. 再断动力电源，换下一颗；贴好标签后安装对应关节。
7. 全部装好接回两条总线分支，只读确认15个唯一ID。

左右均指鸭子自身：

| 从躯干向脚底 | 左侧 | 右侧 | 头颈/嘴 |
|---|---|---|---|
| 第一轴 | 01腿根偏航 | 06腿根偏航 | 11颈根俯仰 |
| 第二轴 | 02髋侧摆 | 07髋侧摆 | 12头部俯仰 |
| 第三轴 | 03髋俯仰 | 08髋俯仰 | 13头部偏航 |
| 第四轴 | 04膝 | 09膝 | 14头部横滚 |
| 第五轴 | 05脚踝 | 10脚踝 | 15嘴部 |

上游servo-web默认 `20–24,30–34,10–14`、官方STAND/FOLD/2048、一键中位校准和IMU200均非本教程默认路径。这里只复用单颗配置功能，不点击它的全机姿态来测试本机。用完关闭上游调试台，释放串口，再进入本项目。

## 3. 核方向，看懂只读输出

支撑机体后逐轴观察小角度，回原位置，再看下一轴。完整增加计数方向表见 [HARDWARE第4节](../HARDWARE.md#4-15个舵机id与已观察方向)。区分舵机计数增减、实际机械前后、模型关节正负；本包保留已核实的计数到实物方向关系。

例如：03增加时左大腿朝嘴巴，08增加时右大腿朝屁股，是安装关系造成的；11增加时颈根后移。若不符合，先核ID与安装，`directions_verified=true`不会替你翻转轴向。

配置好串口后：

```sh
python runtime.py inspect --robot .local/robot.json
```

应有ID1–15全部状态。以下只是**输出字段示例，不是当前实机读数**：

```json
{"motion_writes":0,"state":{"1":{"id":1,"mode":4,"offset":0,"torque":0,"target":0,"pos":2048,"voltage":5.0,"temp":28,"error":0}}}
```

实际输出有15项。`torque=0`是未使能，不代表损坏；`target`是目标、`pos`是测量，不能互相替代。offset是已有硬件状态，只读取保存。坐标、编号、模式异常先确认真实状态，不用取模或“全部写2048”掩盖差异。

## 4. 建立自己的START

START是正确初始站姿的编码快照。同一数字只有在相同安装、硬件模式和offset下才对应同一姿态，不能凭照片反推计数。

| 正面参考 | 侧面参考 |
|---|---|
| ![正面](../media/20261023/onboard-front.jpg) | ![侧面](../media/20261023/onboard-side.jpg) |

核对实际几何关系：

- 躯干正面朝前，腿根没有转了半圈，左右腿不交叉，脚尖朝向一致。
- 两脚底能平放同一平面，不能一只踮脚、一只抬脚。
- 双膝保留弯曲，左右关系接近参考；不为固定身高而把膝拉直。
- 头部不侧歪，头颈位于参考初始位置，线缆不承担支撑。
- X5、电池、小板和附加件固定；装载改变后重新观察站立与单轮效果。

照片不是尺寸治具。目前未发布经实测的髋膝绝对角度及站姿定位尺寸，所以外观看上去相近不等于动力学条件精确一致。成功配置记录和待补实测项见 [样机配置卡](PROTOTYPE_CONFIGURATION.md)。

可逐组保留正确关节，只调整少数未对准关节，不必一次失能15只。使能时不强掰；需要手摆时明确卸力并托住受影响部件，遵循所用工具的实际状态。

支撑并保持姿态不动：

```sh
python runtime.py capture --robot .local/robot.json --output .local/captured_robot.json
```

预期 `motion_writes=0`，输出文件有15个start与offset数值。连续三组位置变化超过10counts时拒绝保存。捕获后 `start_pose_verified`仍false；核实实物及数值后设true，方向确认后设 `directions_verified=true`。保留捕获前文件，审核后的文件用作自己的 `.local/robot.json`。捕获本身不使能、不自动站立。

## 5. IMU安装方向与只读验证

### 5.1 机体坐标与矩阵

机体 `+X` 朝嘴巴、`+Y` 朝鸭子自身左、`+Z` 朝上，组成右手坐标。先找JY901S模块的X/Y/Z正轴标识；排针或线缆朝向不能替代轴标识。

![机体坐标：俯视与侧视](images/body-axes.png)

```text
v_body = R × v_sensor
R第1列：传感器+X在机体坐标中的方向
R第2列：传感器+Y在机体坐标中的方向
R第3列：传感器+Z在机体坐标中的方向
```

以下示例只适用于描述完全相同的轴向安装，**不是本原型的通用安装值**：

| 传感器正轴实际朝向 | body_from_sensor_rotation |
|---|---|
| X前、Y左、Z上 | `[[1,0,0],[0,1,0],[0,0,1]]` |
| X左、Y后、Z上 | `[[0,-1,0],[1,0,0],[0,0,1]]` |
| X后、Y右、Z上 | `[[-1,0,0],[0,-1,0],[0,0,1]]` |

每列都应有明确物理意义，矩阵正交且行列式+1。任意斜装需量清固定角或重新固定到可识别方向，不能随便挑一个“看起来接近”的矩阵。模块固定在刚性躯干，不粘活动头颈、晃动电池或被线缆扯动处。

### 5.2 执行独立只读检查

先结束占用同一串口的其他任务。稳定支撑机体，运行：

```sh
python runtime.py imu-check --robot .local/robot.json --seconds 8
```

只打开IMU口，不要求start填完、不要求 `imu_mount_verified=true`，便于首次验证。JY901S应以115200输出0x53欧拉角和0x52角速度，原型约50Hz；该工具不修改传感器输出配置，需改设置时使用厂商软件。

每约0.25秒输出：

| 字段 | 含义 |
|---|---|
| sensor_angles_deg | 传感器roll/pitch/yaw，度 |
| sensor_gyro_dps | 传感器三轴角速度，度/秒 |
| body_gyro_dps | 由候选矩阵转换的机体三轴角速度 |
| body_gravity_unit | 机体中的重力方向；水平且轴向正确时约[0,0,-1] |
| body_pitch_deg | 与D运行器相同定义的重力俯仰 |
| pitch_delta_deg | 相对本次首帧的变化，正为前倾，负为后倾 |
| angle_age_ms / gyro_age_ms | 主机最后收到相应数据后的年龄，不是传感器全链路延迟 |

托住整机，缓慢整体向嘴巴方向倾几度、回原位，再向后倾几度。预期 `pitch_delta_deg` 前倾时增、后倾时减，回原位接近起点。只动头颈、躯干未动时，躯干IMU不应反映同样的整机倾斜。

结束摘要字段示例如下，**示例数字是理想化演示，不是新增实测结果**：

```json
{
  "action":"imu-check",
  "status":"READ_ONLY_CAPTURE_COMPLETE_DIRECTION_REVIEW_REQUIRED",
  "motion_writes":0,
  "configuration_writes":0,
  "servo_port_opened":false,
  "angle_0x53":{"packets":400,"host_observed_hz":50.0,"max_host_gap_ms":20.0},
  "gyro_0x52":{"packets":400,"host_observed_hz":50.0,"max_host_gap_ms":20.0},
  "bad_checksum":0
}
```

统计依据主机到包时间，USB可能批量送达，不能拿它测传感器端延迟。诊断约每0.25秒采样检查一次；每次检查时，角度或角速度数据年龄超过150ms则报错，不表示恰好停更150ms时立即检测到。人观察方向一致后，才在配置中设 `imu_mount_verified=true`；工具不会自动设置。

成功预设自动前后反馈为0/0，主要靠分段颈角与提前回位。IMU接入与记录不等于全身自平衡已验证。

## 6. 第一次慢复位

托稳躯干头部，双脚卸重，两腿及线缆自由：

```sh
python runtime.py restore --robot .local/robot.json --supported
```

屏幕提前提示，3秒后开始。先将当前读数设为目标，再使能失能关节，最后慢回START。不改硬件标定。结束显示 `COMPLETE_SUPPORTED_RESTORE` 后仍核对实物，不只凭文字放手。

个别轴偏离过大可加 `--partial`；`PARTIAL_SUPPORTED_RESTORE` 和skipped列出剩余关节。剩余关节处理完成后再检查整机，不把部分完成当全部完成。

## 7. 第一次悬空单轮

按 [部署第10节](../DEPLOYMENT.md#10-打开实机控制台) 打开实机页面，确认不是DEMO，选1轮。托稳、双脚离地，勾选本轮就绪，再点运行。

前段准备，随后双腿交替屈伸、头颈按时序配合，最后回START。看是否动错轴、反向、卡碰、持续抖动或头部下垂。完整日志400帧、末目标START只证明程序完成；身体是否跟上需现场观察。悬空通过不直接代表带载能行走。

## 8. 第一次落地与微调

在平整防滑面，以START自行站稳，远离边缘，线缆松弛，有人在旁接护。目标是复现短距离前进，不预设速度或距离。

| 实际现象 | 优先调整 | 其余保持 |
|---|---|---|
| 启动向前倒 | 启动颈角向后少量增加 | 走动角与提前量 |
| 起步正常、走动后倒 | 走动颈角向前少量调整 | 启动角与提前量 |
| 中间前移、最后前倒 | 提前收颈时间增加一点 | 前两段角度 |
| 悬空能动、落地幅度小 | 看目标/实际位置、供电支路、负载及足底接触 | 不同时乱加多个参数 |
| 动错轴、反向、卡碰 | 停止并支撑，核ID和安装 | 不用颈部角掩盖机械错误 |

11号物理方向核对后，正角后移、负角前移。当前默认启动0°、走动请求−30°、保持0秒、过渡0.2秒、提前1.1秒、自动反馈0/0。请求−30°受每拍速度和提前回位影响，不保证达到−30°。

一次只改一项，保持同一装载、地面和起始姿态，记录起步/走动/收步哪一段出问题、是否真正前移、是否需接住。单轮达到现场要求后再探索2/3/5完整轮；多轮稳定性仍需各机验证。

## 9. 保存自己的复刻结果

至少记录发布tag、结构/供电/装载照片、START备份、颈部参数、执行日志、悬空/落地、现场观察和完整视频。配置保留程序输入，视频补充实物跟随与站立表现。

配置与日志位于software/.local。公开前删除凭据、设备序列号及私人网络信息。使用 [Issue模板](https://github.com/Xiaomiju-x/rdk-x5-microduck/issues/new/choose) 分享复刻记录，贡献方法见 [CONTRIBUTING](../CONTRIBUTING.md)。
